Memory Allocator

Complete · malloc/free, built from scratch in C

The idea

malloc() and free() are two of the most-used functions in C, and also two of the easiest to take for granted. This project builds a working allocator from scratch — a fixed memory pool, and hand-written my_malloc() and my_free() functions that manage it — to actually understand what's happening underneath every heap allocation a program makes.

How it works

The allocator manages a fixed 1024-byte pool, carved into variable-sized blocks. Each block stores a small header — its size and whether it's currently free — directly alongside the data it holds.

Allocation uses a best-fit strategy: rather than grabbing the first free block that's big enough (which wastes space), it scans the whole pool and picks the smallest free block that still fits the request. If that block has room left over after the allocation, it gets split — the leftover space becomes a new, independent free block instead of being wasted.

Freeing does the reverse: mark a block free, then scan for opportunities to coalesce — merge it with a neighboring free block into one larger one. Without coalescing, a pool can fragment into lots of small, individually-useless free blocks even when the total free space would easily satisfy a new request.

Proving it works

Three explicit test cases exercise the allocator's actual logic, not just the happy path:

Splitting — free a 64-byte block, then allocate two separate 16-byte blocks and confirm both carve cleanly out of that one freed region.

Coalescing — free two neighboring 32-byte blocks, then request a single 60-byte allocation that couldn't fit in either block alone, proving the allocator actually merged them back into one contiguous space first.

Error handling — request more memory than the entire pool holds, and confirm the allocator fails cleanly with NULL instead of corrupting memory or crashing.

Splitting and coalescing are opposites that have to cooperate — split too eagerly and you fragment the pool with tiny blocks; never coalesce and those fragments become permanently wasted space. Getting both right, together, is most of what makes a real allocator different from a naive one.
